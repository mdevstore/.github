# Support

## Before you post

Most problems are answered faster by one of these:

1. **[Documentation](https://docs.mdevstore.com)** - setup guides, config reference and API docs for every resource
2. **Search [existing issues](https://github.com/mdevstore/md-support/issues?q=is%3Aissue)** - including closed ones
3. **Update to the latest version** - check your Tebex account for a newer release

## Where to go

| What you need | Where |
|---|---|
| Setup help, general questions | [Discord](https://discord.gg/mdevstore) |
| Bug report | [Issue tracker](https://github.com/mdevstore/md-support/issues/new/choose) |
| Feature request | [Issue tracker](https://github.com/mdevstore/md-support/issues/new/choose) |
| Security vulnerability | See [SECURITY.md](SECURITY.md) - **do not open a public issue** |
| Purchases, refunds, licence transfers | Tebex - [mdevstore.com](https://www.mdevstore.com) |
| Security vulnerability in FiveM itself | [Cfx.re forums](https://forum.cfx.re) |

## What makes a report useful

Reports that include the following get resolved considerably faster:

- Resource name **and version** - not "the latest one"
- Your framework - standalone, QBCore, ESX or ox_core
- FiveM artifact version
- Full error output from both the client console (F8) and the server console
- Whether it still happens with other resources stopped

The bug report template asks for all of this. Filling it in properly is the difference between a fix today and three days of back-and-forth.

## What isn't supported

- Modified resource code — if you've edited the source, reproduce it on a clean copy first
- Leaked or resold copies
- Custom development or integration work - ask in Discord and we can discuss it separately
- Framework-specific bugs that aren't caused by the resource
